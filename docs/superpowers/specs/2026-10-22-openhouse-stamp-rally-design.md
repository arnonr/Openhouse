- **วันที่:** 2026-10-22
- **หน่วยงาน:** อุทยานเทคโนโลยี มจพ. (พระจอมเกล้าพระนครเหนือ)
- **LINE Official Account:** `@096ilctj`

## 1. เจตนาและที่มาของระบบ (Intent & Why)
ในงาน Open House ของอุทยานเทคโนโลยี มจพ. จะมีนักเรียนเข้ามาเยี่ยมชมฐานกิจกรรมประมาณ 3–5 ฐาน (จำนวนผู้เข้าร่วมประมาณ 100 คน) ทางหน่วยงานต้องการระบบสะสมแสตมป์ดิจิทัลผ่าน QR Code เชื่อมกับ LINE OA ของหน่วยงาน (`@096ilctj`) เพื่อให้นักเรียนเดินสแกนป้าย QR ประจำฐานได้ด้วยตัวเองอย่างรวดเร็ว เมื่อเก็บแสตมป์ครบทุกฐานแล้วจึงกรอกข้อมูลสั้นๆ และนำหน้าจอไปแสดงต่อเจ้าหน้าที่เพื่อแลกรับของรางวัล พร้อมทั้งช่วยเพิ่มยอดผู้ติดตามใน LINE OA และมีข้อมูลสรุปผลผู้เข้าร่วมงานสำหรับทำรายงานโครงการ

## 2. เป้าหมาย ขอบเขตที่ไม่ทำ และสิ่งที่ต้องหลีกเลี่ยง (Goals, Non-Goals, Anti-Goals)

### เป้าหมาย (Goals)
- **สแกนเข้าฐานได้ทันทีแบบไร้รอยต่อ:** นักเรียนเดินมาสแกนป้าย QR Code ที่ตั้งไว้หน้าฐานแล้วได้รับตราประทับของฐานนั้นทันที โดยไม่ต้องกรอกฟอร์มลงทะเบียนก่อนเริ่มเดินฐาน
- **เก็บข้อมูลสั้นกระชับเมื่อครบฐาน:** เมื่อสะสมแสตมป์ครบทุกฐานที่เปิดใช้งานแล้ว ระบบจึงให้กรอกข้อมูลสั้นๆ แค่ 2 ส่วน (จิ้มเลือกระดับชั้น และพิมพ์ชื่อโรงเรียน) ก่อนปลดล็อกหน้าแลกรับของรางวัล
- **แลกรับของรางวัลหน้างานได้ง่ายและกันการรับซ้ำ:** หน้าจอแลกรางวัลมีเวลาปัจจุบันวิ่งแบบเรียลไทม์ (ป้องกันภาพแคปหน้าจอ) และให้นักเรียนกดปุ่มยืนยันรับของรางวัลต่อหน้าเจ้าหน้าที่เพื่อเปลี่ยนสถานะเป็น "รับรางวัลแล้ว" ทันที
- **เจ้าหน้าที่จัดการฐานและพิมพ์ป้ายเองได้:** มีหน้า Admin สำหรับเพิ่ม/ลด/แก้ไขชื่อฐาน (3–5 ฐาน), สั่งพิมพ์ใบป้าย QR Code ขนาด A4 ประจำฐาน, ดูสถิติผู้เข้าชมรายฐานแบบเรียลไทม์ และดาวน์โหลดข้อมูลผู้เข้าร่วมทั้งหมดเป็นไฟล์ Excel (CSV)
- **รองรับการทดสอบทันทีและเชื่อมต่อ LINE OA ได้ง่าย:** มีโหมดทดสอบผ่านเว็บเบราว์เซอร์ทั่วไป (Demo/Fallback Mode) ให้ทีมงานทดสอบได้ทันทีตั้งแต่ยังไม่ได้ตั้งค่า LIFF ID และเมื่อใส่ `LIFF_ID` แล้วจะดึงชื่อ/รูปโปรไฟล์จาก LINE อัตโนมัติพร้อมตั้งค่าชวนเพิ่มเพื่อน LINE OA (`@096ilctj`)

### สิ่งที่ไม่รวมในขอบเขต (Non-Goals)
- ไม่ทำระบบตัดสต็อกของรางวัลหลายประเภทหรือระบบสุ่มกาชาปอง (เน้นสะสมครบแลกรับรางวัลตามเกณฑ์เดียว)
- ไม่ทำแอปพลิเคชันแยกสำหรับให้สตาฟประจำฐานแต่ละฐานคอยถือเครื่องสแกนเด็ก (เพราะหน้างานวางป้าย QR ให้นักเรียนเดินมาสแกนเอง)
- ไม่ทำระบบสมาชิกซับซ้อนหรือส่งข้อความบรอดแคสต์แยกกลุ่มผ่าน Messaging API ที่เสียค่าโควตาข้อความ

### สิ่งที่ต้องหลีกเลี่ยง (Anti-Goals)
- **ห้ามให้นักเรียนกรอกฟอร์มยาวน่ารำคาญ:** ห้ามถามเบอร์โทร อีเมล เลขบัตรประชาชน หรือคำถามหลายข้อตอนเริ่มสแกนฐานแรก
- **ห้ามใช้ระบบที่นับแต่แต้มรวมโดยไม่แยกฐาน:** ต้องป้องกันไม่ให้นักเรียนสแกนป้าย QR ของฐานเดิมซ้ำๆ เพื่อให้ครบจำนวนแต้ม

## 3. ข้อจำกัดและสภาพแวดล้อม (Constraints)
- **จำนวนผู้ใช้งาน:** ประมาณ 100 คนตลอดงาน
- **เซิร์ฟเวอร์ของหน่วยงาน:** Ubuntu Server ที่มี Nginx Proxy Manager (NPM) และโดเมนที่รองรับ HTTPS อยู่แล้ว (`https://it.technopark.kmutnb.ac.th/`)
- **ข้อกำหนดของ LINE LIFF และการเปิดกล้องบนเว็บ:** ต้องรันภายใต้ `https://` เท่านั้น

## 4. แนวทางที่พิจารณาและแนวทางที่เลือก (Approaches)

1. **แนวทางที่ 1 (แนวทางที่เลือก): LINE LIFF Web App + Node.js + SQLite รันผ่าน Docker Container เดียว**
   - *การทำงาน:* เว็บแอปเชื่อมต่อ LINE LIFF SDK คู่กับ Backend Node.js (Express) และฐานข้อมูล SQLite เก็บลงไฟล์ในโฟลเดอร์ Volume ของ Docker
   - *ข้อแลกเปลี่ยน:* ต้องตั้งค่า LIFF ID ใน LINE Developers Console (ใช้เวลาประมาณ 5 นาที) แต่ได้ประสบการณ์ใช้งานที่ลื่นไหลที่สุด ผูกบัญชี LINE นักเรียนได้แม่นยำ ไม่หลุดเมื่อเปลี่ยนแอปสแกน และติดตั้งบน Ubuntu Server ด้วย Docker คำสั่งเดียว
2. **แนวทางที่ 2: LINE Chatbot (ส่งข้อความรหัสฐานเข้าแชท + Flex Message)**
   - *ข้อแลกเปลี่ยน:* เห็นการ์ดในแชท แต่ขั้นตอนกรอกข้อมูลก่อนรับรางวัลและหน้าจอนาฬิกาวิ่งกันแคปจอทำในแชทไม่ได้ ต้องเด้งออกหน้าเว็บอยู่ดี ทำให้ซับซ้อนเกินจำเป็น
3. **แนวทางที่ 3: Web App ทั่วไปจำสถานะผ่านเบราว์เซอร์ (ไม่ใช้ LINE LIFF)**
   - *ข้อแลกเปลี่ยน:* ไม่ต้องตั้งค่า LIFF แต่ดึงชื่อ LINE อัตโนมัติไม่ได้ ชวนแอดเพื่อน LINE OA ไม่ได้ และหากนักเรียนสแกนป้ายแรกด้วยแอปกล้องปกติแต่สแกนป้ายที่สองด้วยแอป LINE ข้อมูลแสตมป์จะแยกกันคนละเบราว์เซอร์

## 5. รายละเอียดการออกแบบระบบ (System Design)

### 5.1 ลำดับการใช้งานของนักเรียน (Student Flow)
1. **สแกนป้าย QR หน้าฐาน:**
   - ป้าย QR ประจำฐานแต่ละฐานจะมีลิงก์เข้าสู่ LIFF URL พร้อมพารามิเตอร์รหัสลับของฐาน เช่น `?booth=BOOTH_TOKEN` (และรองรับการสแกนจากปุ่มกล้องในหน้าเว็บแอปเองด้วย)
   - เมื่อเปิดขึ้นมา ระบบดึง `userId`, `displayName`, `pictureUrl` จาก LINE LIFF อัตโนมัติ และบันทึกตราประทับของฐานนั้นให้ทันทีพร้อมแสดงข้อความแจ้งเตือนว่าเช็คอินสำเร็จ
   - **การลดโอกาสสแกนรัว/ส่งรูปป้ายต่อกัน (การตัดสินใจของผู้พัฒนา - Builder Call):** มีค่าตั้งต้นหน่วงเวลา (Cooldown) ระหว่างการสแกนฐานถัดไป เช่น 60 วินาที (ซึ่ง Admin สามารถปรับเป็น 0 วินาทีหรือเปลี่ยนเวลาได้ในหน้าตั้งค่าหลังบ้าน)
2. **กรอกข้อมูลสั้นๆ เมื่อสะสมครบทุกฐาน:**
   - เมื่อจำนวนแสตมป์ที่สะสมครบตามจำนวนฐานที่เปิดใช้งาน (Active Booths) ปุ่ม **"กรอกข้อมูลสั้นๆ เพื่อรับของรางวัล"** จะปรากฏขึ้น
   - นักเรียนกรอกเพียง 2 ช่อง:
     1. **ระดับชั้น** (ปุ่มกดเลือก: `ม.ต้น`, `ม.ปลาย`, `ปวช. / ปวส.`, `นักศึกษา / อื่นๆ`)
     2. **โรงเรียน / สถาบัน** (ช่องพิมพ์ข้อความสั้นๆ)
3. **หน้าแสดงสิทธิ์และกดยืนยันรับของรางวัล:**
   - แสดงชื่อนักเรียน ระดับชั้น โรงเรียน สถานะเก็บครบทุกฐาน และ **นาฬิกาเวลาจริงวิ่งระดับวินาทีพร้อมแอนิเมชัน** เพื่อป้องกันการใช้ภาพแคปหน้าจอ
   - เมื่ออยู่ต่อหน้าเจ้าหน้าที่จุดแลกของรางวัล นักเรียนกดปุ่ม **"กดยืนยันรับของรางวัล (ต่อหน้าเจ้าหน้าที่)"** (มีกล่องยืนยัน 1 ครั้งกันมือลั่น) เมื่อกดแล้วจะบันทึกเวลา `redeemed_at` ลงฐานข้อมูลและเปลี่ยนหน้าจอเป็นสถานะ **"รับของรางวัลเรียบร้อยแล้ว"** ทันที

### 5.2 ระบบจัดการสำหรับเจ้าหน้าที่ (Admin Panel)
- เข้าถึงผ่าน `/admin` โดยใส่รหัสผ่านผู้ดูแลระบบ (`ADMIN_PASSWORD` ตั้งค่าผ่านไฟล์ `.env`)
- **ฟีเจอร์ในหน้า Admin:**
  1. **ภาพรวมสถิติเรียลไทม์:** จำนวนผู้เข้าร่วมทั้งหมด, จำนวนคนที่สะสมแสตมป์ครบ, จำนวนคนที่แลกรับรางวัลแล้ว และยอดสแกนแยกตามแต่ละฐาน
  2. **จัดการฐานกิจกรรม (Booth Management):**
     - มีฐานตั้งต้นให้ 4 ฐาน (สามารถเพิ่มเป็น 5 ฐาน ลดเหลือ 3 ฐาน หรือแก้ไขชื่อ/คำอธิบาย/ไอคอนของแต่ละฐานได้ตลอดเวลา)
     - ปุ่ม **"พิมพ์ป้าย QR ประจำฐาน"** ที่เปิดหน้ากระดาษขนาด A4 สวยงามพร้อมชื่อหน่วยงาน ชื่อฐาน และ QR Code ขนาดใหญ่สำหรับสั่งพิมพ์ (Print / Save as PDF) ไปติดหน้าฐานได้ทันที
  3. **จัดการค่าตั้งค่าระบบ:** ปรับจำนวนวินาทีหน่วงเวลาระหว่างฐาน (Cooldown) ได้ตามสถานการณ์หน้างาน
  4. **รายชื่อผู้เข้าร่วมและปุ่ม Export CSV:** ดูตารางรายชื่อนักเรียน ค้นหา/กดเปลี่ยนสถานะรับรางวัลแทนนักเรียนได้ในกรณีฉุกเฉิน และกดดาวน์โหลดไฟล์ `.csv` (รองรับภาษาไทยใน Excel ด้วย UTF-8 BOM)

### 5.3 โครงสร้างฐานข้อมูล (SQLite Schema)
เก็บข้อมูลในไฟล์ `./data/openhouse.db` เพื่อให้สำรองข้อมูลและรันใน Docker ได้ง่าย:
- `booths`: `id`, `code` (รหัสลับเฉพาะฐานสำหรับสร้าง QR), `name`, `description`, `icon`, `sort_order`, `is_active`, `created_at`
- `participants`: `line_user_id` (PK), `display_name`, `picture_url`, `grade_level`, `school_name`, `is_redeemed`, `redeemed_at`, `created_at`, `updated_at`
- `stamps`: `id`, `line_user_id`, `booth_id`, `scanned_at` (Unique constraint บน `(line_user_id, booth_id)` ป้องกันการได้แสตมป์ฐานเดิมซ้ำ)
- `settings`: `key` (PK), `value` (เก็บค่า เช่น `event_title`, `cooldown_seconds`, `required_stamps_mode`)

### 5.4 การติดตั้งบน Ubuntu Server + Nginx Proxy Manager และการผูก LINE OA (`@096ilctj`)
- ใช้ `Dockerfile` และ `docker-compose.yml` รันพอร์ตภายใน (เช่น `3100`) พร้อมเชื่อมโฟลเดอร์ `./data` เก็บไฟล์ SQLite บนเครื่องเซิร์ฟเวอร์
- ใน Nginx Proxy Manager สามารถชี้ Proxy Host (เช่น `openhouse.technopark.kmutnb.ac.th`) หรือ Custom Location ภายใต้ `https://it.technopark.kmutnb.ac.th/` มายังพอร์ต `3100`
- มีคู่มือภาษาไทยแบบจับมือทำสำหรับการตั้งค่า LINE LIFF และการสร้างปุ่ม Rich Menu ใน `manager.line.biz/account/@096ilctj`

## 6. สิ่งที่ผู้พัฒนาตัดสินใจให้ (Builder Calls)
- **โหมดทดสอบอัตโนมัติ (Demo Mode):** หากยังไม่ได้ใส่ค่า `LIFF_ID` ใน `.env` ระบบจะจำลองผู้ใช้ให้นักเรียน/ทีมงานกดทดสอบสแกนครบทุกขั้นตอนบนเบราว์เซอร์ได้ทันที
- **การสแกน QR Code รองรับ 2 ทาง:** นักเรียนสามารถสแกนป้าย QR ด้วยกล้องมือถือ/กล้องแอป LINE จากข้างนอกได้เลย หรือจะกดปุ่ม "สแกน QR ฐานถัดไป" จากข้างในหน้าเว็บแอปก็ได้
- **การเปิดไฟล์ CSV ใน Microsoft Excel:** ใส่รหัส UTF-8 BOM (`\uFEFF`) ให้ไฟล์ CSV เสมอ เพื่อไม่ให้ชื่อโรงเรียนและชื่อนักเรียนภาษาไทยเพี้ยนเมื่อเปิดด้วยโปรแกรม Excel
